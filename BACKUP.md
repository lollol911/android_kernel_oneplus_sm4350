## What is NOT in this repo (must be recreated)

1. **`KernelSU/`** (the ReSukiSU driver). `drivers/kernelsu` is a symlink to `../KernelSU/kernel`, and `KernelSU/` itself is not tracked.
   ```
   git clone https://github.com/Baka-SU/BakaSU KernelSU
   git -C KernelSU checkout 239e1e88        # tag v4.2.0-rc3
   ls -l drivers/kernelsu                   # should point at ../KernelSU/kernel
   ```
   If the symlink is missing: `ln -s ../KernelSU/kernel drivers/kernelsu`.
   If checkout complains about CRLF noise in `manager/gradlew.bat`, use `git -C KernelSU checkout -f --detach 239e1e88`.
2. **`out/`** (build output) — regenerated by the build.
3. **Your stock/backup files**: a copy of the original boot and vendor_boot images, the stock vendor modules used for the module compatibility check (`~/ksunext_backup/flat_modules`), and the unpacked ramdisk plus `mkbootimg.py` used for packing. Keep these somewhere safe outside git.

## Build

```
git switch wireguard-bbr
# recreate KernelSU/ as above
make O=out ARCH=arm64 LLVM=1 vendor/holi-qgki_defconfig
```

**Config gotcha:** `olddefconfig` does not pick up changed choice or string options from the defconfig once `out/.config` already has a value. If you are reusing an old `out/`, edit `out/.config` directly (or delete `out/` and start clean), then run:

```
make O=out ARCH=arm64 LLVM=1 olddefconfig
make O=out ARCH=arm64 LLVM=1 -j$(nproc)
```

Options that must be set in the final `out/.config`:

```
CONFIG_KSU=y
CONFIG_KSU_SUSFS=y                 # inline-hook mode; CONFIG_KSU_MANUAL_HOOK must be off
CONFIG_BBG=y
CONFIG_LSM="lockdown,yama,loadpin,safesetid,integrity,selinux,smack,tomoyo,apparmor,baseband_guard"
CONFIG_TCP_CONG_ADVANCED=y
CONFIG_TCP_CONG_BBR=y
CONFIG_NET_SCH_FQ=y
CONFIG_WIREGUARD=y
CONFIG_LOCALVERSION="-qgki-g3f1024c3bf97"
CONFIG_DEFAULT_TCP_CONG="cubic"
```

The kernel release must stay `5.4.300-qgki-g3f1024c3bf97` so the stock vendor modules still load. After any config change, compare the `modprobe --dump-modversions` output of each stock module against the same-named built module (after `make ... INSTALL_MOD_PATH=modules_out modules_install`); there must be no differences.

## Pack and flash

```
python3 mkbootimg.py --kernel out/arch/arm64/boot/Image --ramdisk unpacked/ramdisk \
  --os_version 15.0.0 --os_patch_level 2025-11 --header_version 3 -o new_boot.img
```

vendor_boot is left untouched. Flash to the spare A/B slot (`fastboot flash boot_<other>`), then `fastboot --set-active=<other>`. To go back, set the previous slot active again.

## Userspace that goes with it

- ReSukiSU manager v4.2.0-rc1 to rc3 (the kernel is rc3, version code 35171). First boot on a new driver: open the manager, re-grant root, reboot once.
- SUSFS runtime config: BRENE module v0.0.71 (it ships its own `susfs` binary; the old susfs4ksu module must stay disabled).
- Shamiko needs a copy of its zip patched to skip the "kernel version >= 20000" install check.
- WireGuard app: grant it root, then Settings → Advanced → "Enable kernel module load". A tunnel's interface then shows as type `wireguard` in `ip -d link show`.
- BBR is not the default. Switch at runtime with `echo bbr > /proc/sys/net/ipv4/tcp_congestion_control`.
- Baseband Guard has `CONFIG_BBG_BLOCK_BOOT` and `CONFIG_BBG_BLOCK_RECOVERY` off, so boot and recovery partitions stay writable.

## Known issues

- The dirtysepolicy bypass module does not work on the ReSukiSU builds (not needed).
- KPM is not available on rc3 and was deliberately not added.
- `TCP_CONG_ADVANCED` also builds `tcp_bic`, `tcp_htcp` and `tcp_westwood` as modules; they are never installed on the phone.
